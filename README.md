# Remote To Local Copy(RTLC)

    0. Web UI (настройки, статус, управление в браузере):
        a. pip install -r requirements.txt
        b. python webui.py
        c. Открыть http://127.0.0.1:8765/ — с loopback пускает без ключа;
           для сетевых клиентов нужен заголовок X-API-Key (config.ini [Web] api_key,
           генерируется автоматически при первом запуске).
        d. Вкладки: Статус (метрики, управление движком, последние файлы),
           Файлы (журнал копий), Лог, Настройки (весь config.ini, движок
           перезапускается после сохранения).
        [Web] в config.ini: host (по умолчанию 127.0.0.1), port (8765),
        api_key, trust_loopback (true — локальные запросы без ключа).
    1. Install to Windows(x64):
        a. Скачать 'dist/rtlc.exe'.
        b. Закинуть бинарь в рабочую директорию (Например: 'C:/rtlc/').
        c. Режимы запуска:
           - 'rtlc.exe' (или 'rtlc.exe gui') — Web UI на http://127.0.0.1:8765/
             (при первом запуске создаёт config.ini и ждёт настройки через браузер);
           - 'rtlc.exe run' — консольный цикл копирования без Web UI;
           - служба Windows (SMB-режим): командная строка от имени администратора,
             'C:/rtlc/rtlc.exe install', затем 'rtlc.exe start' / 'stop' / 'remove'.
        d. Сборка exe из исходников:
           python -m venv .venv && .venv/Scripts/pip install -r requirements.txt pyinstaller pywin32 pysmb
           .venv/Scripts/python.exe -m PyInstaller rtlc.spec --clean --noconfirm
           (результат: dist/rtlc.exe, режимы: gui/run/service; версия — file_version_info.txt)
    2. Install to RedOS:
        a. Скачать файлы: 'rtlc.py, config.py, install_rtlc.sh'.
        b. Закинуть файлы в домашнюю директорию (Например: '/home/lins/').
        c. Выдать права: 'chmod 755 /home/lins/install_rtlc.sh', запустить его и следовать инструкции установочного скрипта.
    Config.ini:
        [Options]
        1. start_date - дата и время создания файлов от которых начинать сканирование (игнорируется при заданном параметре last_file).
        2. last_file - timestamp от которого начинать сканирование файлов, подставляется автоматически.
        3. refresh_time - интервал между сканированием файлов (в секундах)
        4. extenstion_file - фильтр по расширениям файлов (Пример: '.dcm, .png'), если не нужен фильтр оставляем пустым
        5. stabilize_time - окно стабилизации файла (в секундах, по умолчанию 5): файл копируется только если его размер и время изменения не менялись в течение этого окна. Должно превышать максимальную паузу между записями модальности (для КТ/МРТ рекомендуется 30-60).
        [Paths]
        1. remote - путь до удалённой папки
        2. local - путь до локальной папки
        [Logs]
        1. level - уровень логирования
        2. size - максимальный размер файла логов (в мегабайтах)
        3. backups - количество бекапов логов (создаются в случае достижения максимального размера основного файла логирования)
    State:
        rtlc.state.json - журнал скопированных файлов (путь -> размер/mtime/имя копии). Удаление приведёт к повторному копированию (потерь не будет).
        Копирование атомарно: временные файлы '.rtlc-part-*' в папке назначения + rename; недокопированные остатки удаляются при старте.
    Tests:
        python -m pytest tests/ -v  (только локальные temp-папки, синтетические файлы)
