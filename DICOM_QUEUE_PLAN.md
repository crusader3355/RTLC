# Очередь отложенной DICOM-отправки (RTLC) — план и итоги

> Статус: **реализовано** (коммиты см. в git log ветки
> `fix/medical-copy-hardening`). Исходный план скорректирован по решению
> пользователя: **spool-диска нет** — при недоступности назначения
> исследования ждут в папке-источнике, в БД (`rtlc.state.json`) ведутся
> записи о недоставленных файлах с планом повторов.

## Как работает сейчас (реализовано)

```
walker (поток движка)                DicomQueue (поток-демон)
─────────────────                     ─────────────────────────
scandir → стабилизация                тик queue_tick (default 5 с)
deliver():
  to_folder: копия temp+rename        if breaker OPEN:
  to_dicom: постановка в очередь        C-ECHO-проба каждые 30 с
  (ledger: dicom.queued)              иначе: все файлы, у которых
  └── файл уходит из активного          next_attempt наступил,
      бэклога → walker не               читаются ИЗ ИСТОЧНИКА
      блокируется узлом                 и шлются C-STORE
```

- **Ошибки классифицируются** как раньше (`dicom_sender.send_file`):
  `0x0000`/`0xBxxx` — успех; транзиентные (сеть/ассоциация/0xA7xx) —
  backoff; перманентные (не DICOM/0xCxxx) — парковка без ретрая.
- **Backoff per-file**: `retry_initial` (30 с) → ×2 → `retry_max`
  (600 с), ±20% jitter. Следующая попытка не раньше `next_attempt`.
- **Circuit breaker**: `breaker_threshold` (5) транзиентных фейлов
  подряд → OPEN, пауза `breaker_cooldown` (120 с), затем проба C-ECHO
  каждые 30 с; успех → drain. Счётчик общий на узел, не на файл.
- **Quarantine**: источник исчез до доставки → запись финализируется
  (`quarantine`), ERROR в лог + алерт в GUI; повтор невозможен.
- **Потокобезопасность**: ledger ходит под `state_lock` (RLock) со
  стороны walker'а (`deliver()`) и очереди (`_send`).
- **Переживает рестарт**: очередь восстанавливается из ledger
  (`queued`-записи), источники читаются заново при попытке.
- **GUI**: вкладка «Очередь DICOM» (счётчики, breaker, возраст, таблица,
  кнопки «Отправить сейчас» / «Очистить permanent» с архивом в CSV);
  настройки очереди в форме (retry_initial/max, breaker, tick).
- **API**: `GET /api/v1/dicom/queue`, `POST .../queue/retry_now`,
  `POST .../queue/purge_permanent` (CSV-архив в `Logs/`).

## Папочный сток при недоступном назначении

Без изменений по сути и по решению пользователя: файл ждёт в источнике,
walker держит его в бэклоге и ретраит каждый цикл; запись в ledger
появляется только после успеха (бэклог пересчитывается каждый цикл,
отдельная запись не нужна).

## Тесты (tests/test_dicom_send.py, 13 штук)

Реализованы: оба стока; только DICOM без папки; узел лежит→поднялся
(нет дубля в папке, walker не заблокирован); не-DICOM → permanent;
валидации; C-ECHO up/down; backoff растёт; breaker открывается и держит
паузу; quarantine при исчезновении источника; очередь переживает рестарт.
Итог прогона: 38/38.

## Осознанные ограничения / на будущее

- **Окно риска**: файл, удалённый из источника ДО первой попытки отправки
  (и `to_folder=false`), потерян для DICOM-стока — walker его больше не
  увидит. Окно малое (до первого тика очереди), полностью закрывается
  только spool'ом (отклонён). Митигация: источник — шара модальности,
  файлы там живут до забора PACS.
- **SMB-режим**: каждая попытка качает файл со шары (`_localSource`);
  локальная копия (`to_folder=true`) для ретраев не используется —
  проще и соответствует «ждут в источнике».
- **FIFO**: отправка по `queued_at`; study-level группировка не делалась.
- **Автоочистка permanent**: не реализована — есть кнопка «Очистить
  permanent» с CSV-архивом (`Logs/dicom_permanent_*.csv`).
