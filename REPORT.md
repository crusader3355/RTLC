## 1. Архитектура приложения

```
┌──────────────────────────────────────────────────────────────────┐
│ rtlc.py (CopyUtility)          — локальный режим                 │
│ service.py (CopyUtilityNetShare + MyServiceFramework)            │
│                                — служба Windows (pywin32) + SMB  │
│ smb_client.py (SmbClient)      — smbprotocol, SMB2/3, порт 445   │
│ config.py (Config)             — config.ini, watermark last_file │
└──────────────────────────────────────────────────────────────────┘

Цикл (rtlc.py:210-214, service.py:49-51):
  while True: walker(); sleep(refresh_time)

walker() (rtlc.py:156-175):
  1. scandir() — рекурсивный os.scandir источника;
     фильтр: расширение И st_ctime > watermark        (rtlc.py:177-190)
  2. sort по (ctime, путь)
  3. watermark = max(ctime найденных)   ← ДО копирования (rtlc.py:162)
  4. для каждого: shutil.copy2 → local/<uuid4>.<ext>   (rtlc.py:163-169)
     успех → удалить из очереди; неуспех → оставить
  5. config.save()  (watermark → config.ini)           (rtlc.py:173-174)
  6. saveQueue()    (нескопированные → rtlc.queue)     (rtlc.py:175)

Состояние между перезапусками:
  - config.ini [Options] last_file — watermark (единственный критерий «уже обработано»)
  - rtlc.queue — список имён файлов, не скопированных в прошлом цикле
    (loadQueue, rtlc.py:130-139)
```

## 3. Найденные проблемы

### КРИТИЧНЫЕ (потеря/порча данных)

**К1. Копирование недописанного файла (нет стабилизации)**
`rtlc.py:185-188` — любой файл с `ctime > watermark` немедленно копируется.
Модальность пишет исследование частями → в PACS уходит обрезок; из-за
watermark (см. К3) файл больше никогда не будет скопирован — **порча
исследования без шанса на восстановление**.
Воспроизведение: `test_slow_write_copied_only_after_complete` FAILED —
файл, пишущийся в 2 приёма с паузой, скопирован первым же циклом в
обрезанном виде (1/3 содержимого).

**К2. Неатомарная запись в назначение — PACS видит частичные файлы**
`rtlc.py:164` — `copy2(src, local/<uuid>.dcm)`: файл виден в назначении с
первого байта записи. PACS, мониторящий папку, забирает недокопированный
файл. При обрыве сети/диска частичный файл **остаётся навсегда** (очистки
нет). В SMB-режиме то же (`smbclient.py:33-35`).
Воспроизведение: `test_no_partial_file_visible_in_destination` FAILED —
запись идёт напрямую в финальное имя.

**К3. Watermark как единственный критерий — потеря файлов**
`rtlc.py:162` — watermark выставляется в max(ctime) **до** копирования и
сохраняется в config.ini (`rtlc.py:173-174`) даже при неуспехе части файлов:
- файл, восстановленный со старым creation time (robocopy /COPYALL,
  бэкап, перенос), имеет ctime < watermark → **молча потерян навсегда**;
- окно между `config.save()` и `saveQueue()` (`rtlc.py:173-175`): падение
  процесса → файл вычеркнут из обоих хранилищ → потерян;
- `saveQueue` пишется неатомарно (`rtlc.py:141-146`) — обрыв записи =
  усечённая очередь;
- семантика `st_ctime` разная: Windows — creation time, Linux — inode
  change time (touch/chmod «обновляет» старый файл → лишний дубликат).
Воспроизведение: `test_old_timestamp_file_not_lost` FAILED — файл с
creation time 2001 года, появившийся после ухода watermark, не скопирован.

**К4. Падение посреди цикла → дубли + мусор в назначении**
При падении процесса посреди пачки (ни config, ни queue не сохранены)
рестарт сканирует по старому watermark и копирует уже скопированные файлы
повторно (**дубли с новыми uuid в PACS**), а недописанный файл остаётся
лежать в назначении без какой-либо пометки.
Воспроизведение: `test_restart_mid_copy_no_duplicates_no_leftovers`
FAILED — после «рестарта» в назначении 4 файла вместо 2: полная копия,
PARTIAL-обрезок и два дубля.

**К5. Нет защиты от петель**
Валидации `remote`/`local` нет (`rtlc.py:86-96`). Если назначение внутри
источника (или равны) — скопированные `uuid.dcm` попадают в следующее
сканирование и копируются снова: **бесконечный цикл с экспоненциальным
ростом**, переполнение диска.
Воспроизведение: `test_local_inside_remote_rejected`,
`test_local_equals_remote_rejected` FAILED — приложение стартует с
петлёй в конфигурации.

### ВАЖНЫЕ

**В1. Перезапись файла тем же именем молча игнорируется (Windows)**
Перезапись существующего файла сохраняет его creation time → ctime ≤
watermark → обновлённое исследование **не отправляется в PACS**.
(На Linux — наоборот, безусловный дубликат.)
Воспроизведение: `test_resend_same_name_new_content_not_lost` FAILED.

**В2. Расширения сравниваются case-sensitive**
`rtlc.py:184-186` — `name.endswith(('.dcm',))` пропускает `IMAGE.DCM` —
типичный случай для медицинских архивов.
Воспроизведение: `test_cyrillic_spaces_nested_uppercase_extension` FAILED
(файл `.DCM` потерян, кириллица/пробелы при этом работают).

**В3. SMB-режим: нет фильтра расширений, нет переподключения, нет защиты от исключений**
`smbclient.py:41-50` — `scandir` игнорирует `extension_file` (копируется
всё подряд, включая служебные файлы модальности) и не обёрнут в try:
обрыв SMB-сессии → исключение `listPath` → `walker` падает → **служба
умирает до ручного перезапуска**. `connect()` один раз при старте
(`service.py:19-27`), переподключения нет.

**В4. Необработанное исключение в главном цикле убивает процесс**
`rtlc.py:210-214` и `service.py:49-51` — `walker()` без try/except;
`install_rtlc.sh`/`rtlc.service` — systemd unit без `Restart=`.
Один нештатный файл/папка = остановленный сервис.

**В5. Остановка службы неаккуратна**
`service.py:38-42,59-62` — `SvcStop` ставит флаг, но поток спит в
`sleep(refresh_time)`; SCM может убить процесс посреди копирования
(→ частичный файл, см. К2). `service_impl` не инициализирован до
`SvcDoRun` — stop до run даст AttributeError.

**В6. Логирование недостаточно для расследований**
Нет размера/времени копирования/хеша; ошибки копирования — `print()`
(`rtlc.py:197`, `smbclient.py:38`) — в контексте службы stdout потерян;
размер очереди не логируется, отставание не видно.

### МИНОРНЫЕ (зафиксировано, без исправлений)

- `logging.basicConfig(handlers='')` (`rtlc.py:51`) — бессмысленный вызов.
- `entry.stat()` вызывается дважды на файл (`rtlc.py:185-188`).
- Логгер назван `'rltc'` вместо `'rtlc'` (`rtlc.py:60`).
- Лог времени файла — в UTC (`gmtime`), watermark из `start_date` — в
  локальном времени (`mktime`): путаница при чтении логов, на корректность
  не влияет.
- `config.save()` перезаписывает весь ini каждый цикл (в т.ч. пароль SMB)
  и неатомарно.
- `dist/rtlc.exe` — собранный бинарь в git; после исправлений потребуется
  пересборка, иначе в продакшене останется старый код.
- Длинные пути (>260) — на тестовой машине работают (CPython long-path
  aware), но зависят от ключа реестра `LongPathsEnabled` на целевой машине.

- Базовое копирование с побайтовым совпадением, вложенные подпапки.
- Всплеск 520 файлов — потерь нет.
- Недоступность назначения → повторные попытки → восстановление.

## 5. План исправлений (по степени критичности)

1. **Стабилизация источника** (К1): файл копируется только если
   (size, mtime) не изменились между двумя сканированиями и с первого
   обнаружения прошло ≥ `stabilize_time` (новая опция, default 5 сек).
2. **Атомарная запись** (К2): копия в `<local>/.rtlc-part-<uuid>` (тот же
   том) → `os.replace` в финальное имя; `finally`-очистка temp; при старте
   удаление устаревших `.rtlc-part-*`. Явный chunked copy
   (`shutil.copyfileobj` + `copystat`) вместо `copy2`.
3. **Persisted state** (К3, К4, В1): ledger `rtlc.state.json` (атомарная
   запись tmp+replace, сохранение после **каждого** файла):
   `{путь: {size, mtime, dest}}`. Сканирование больше не фильтруется
   watermark'ом; путь не в ledger → копия; size/mtime изменились → новая
   копия (новый uuid, в логе — «re-sent»); совпадает → пропуск.
   Watermark в config.ini сохраняется для совместимости.
4. **Защита от петель** (К5): при старте — отказ (SystemExit), если
   realpath назначения совпадает с источником или вложен в него.
5. **Живучесть** (В4, В5): try/except вокруг `walker()` в обоих циклах;
   per-entry защита в `scandir`; `threading.Event` вместо `sleep` для
   мгновенной остановки службы; `Restart=on-failure` в systemd unit.
6. **Регистр расширений** (В2): сравнение в нижнем регистре.
7. **SMB parity** (В3): фильтр расширений в `smbclient.scandir`, try вокруг
   `listPath`, переподключение при обрыве (закрывается общим механизмом
   temp+replace, т.к. назначение локальное). *Локально не тестируется —
   SMB-сервера нет; изменения минимальны и симметричны локальному режиму.*
8. **Логирование** (В6): размер, длительность, длина очереди в каждом
   цикле; `print` → `log.error`.

Каждое исправление — отдельный коммит, после каждого — прогон всего
набора тестов. Рефакторинг вне перечисленных проблем не выполняется.

## 7. Что сознательно оставлено и почему

- **Окно стабилизации — конфигурационная гарантия.** Никакое polling-окно
  не отличает «файл записан полностью» от «писатель сделал паузу».
  `stabilize_time` должен превышать максимальную паузу между записями
  модальности (рекомендуется 30–60 с для КТ/МРТ, default 5 с).
- **Перезапись тем же именем → новая uuid-копия**, старый файл не
  удаляется: PACS мог уже забрать первую версию. Дубликаты SOPInstanceUID
  разруливаются на стороне PACS; событие помечается в логе `(re-sent)`.
- **Ledger растёт неограниченно** (по записи на файл). В медконтуре это
  осознанный выбор: история важнее компактности. При необходимости —
  ротация отдельной задачей.
- **Одинаковые (size, mtime) при разном содержимом** неотличимы без
  хеширования всего файла — принятый остаточный риск (на практике mtime
  меняется при перезаписи).
- **Длинные пути (>260)** зависят от `LongPathsEnabled` в реестре целевой
  машины; на тестовой — работают.
- `dist/rtlc.exe` пересобран PyInstaller'ом (`rtlc.spec`) после всех
  исправлений ветки, включая SMB2/3 и DICOM-доставку.
- **Логгер называется `'rltc'`** (опечатка) — не переименован, чтобы не
  ломать существующие разборы логов.
- **SMB2/3 и служба проверены динамически** — см. §12: end-to-end прогон
  под SCM с реальной loopback-шарой, копия побайтово идентична.

## 8. Как запустить приложение и тесты локально

```bash
# Приложение (Python 3.10+ для GUI; для SMB-режима: pip install smbprotocol pywin32)
mkdir remote local
python rtlc.py          # первый запуск сгенерирует config.ini и выйдет
# отредактировать config.ini: [Paths] remote/local, [Options] extension_file,
#                          stabilize_time, refresh_time
python rtlc.py

# Служба Windows (SMB-режим): rtlc.exe install && rtlc.exe start
# Linux/RedOS: sudo ./install_rtlc.sh

# Тесты (только локальные temp-папки, синтетические данные):
python -m pytest tests/ -v
```

Новая опция `config.ini → [Options] → stabilize_time` (секунды, default
5): файл копируется только после окна тишины такой длины. Состояние —
`rtlc.state.json` рядом с приложением; удаление файла состояния приведёт
к повторному копированию (без потерь).

## 9. Веб-интерфейс (webui.py, по аналогии с cdcm2pacs)

`python webui.py` поднимает FastAPI + uvicorn (по умолчанию
`http://127.0.0.1:8765/`): движок копирования работает в фоновом потоке,
все настройки и статус — через браузер (`static/index.html`, без сборки).

- **API**: `GET /api/v1/status`, `POST /api/v1/control/{start|stop|restart|scan_now}`,
  `GET/PUT /api/v1/config` (секреты маскируются `***`, петля путей
  отклоняется до записи), `GET /api/v1/ledger` (журнал копий, работает и
  при остановленном движке — читает state с диска), `GET /api/v1/log`,
  `GET /health`, WebSocket `/ws` (push статуса, UI откатывается на polling).
- **Безопасность** (идиома cdcm2pacs): `X-API-Key` (генерируется при
  первом запуске в `[Web] api_key`), trusted-loopback без ключа
  (клиент + Host — loopback, защита от DNS rebinding), rate limit
  600 req/min для сетевых клиентов, host по умолчанию 127.0.0.1.
- **Движок**: `CopyUtility.run_forever()` (общий цикл для CLI, службы и
  GUI), метрики `stats` (циклы/скопировано/ошибки/последний цикл),
  deque последних 50 копий, `status()` — снимок для API. В ledger
  добавлено поле `copied_at`.
- **Тесты**: `tests/test_webui.py` (8 штук, TestClient): auth 401/403/200,
  маскировка секретов, валидация и отказ петли в PUT, полный цикл
  «старт → файл скопирован → стоп» через HTTP, ledger с диска, хвост лога.
- **Smoke-проверка на живом сервере**: uvicorn на 127.0.0.1:8765, файл
  `.dcm` скопирован движком и подтверждён побайтово через
  `/api/v1/status` + `/api/v1/ledger`, control stop/start по HTTP.
- Зависимости: `requirements.txt` (fastapi, uvicorn, websockets), dev —
  `requirements-dev.txt` (+pytest, httpx). Для GUI нужен Python 3.10+
  (ядро rtlc.py остаётся совместимым с более старыми версиями).
- **Форма настроек типизирована** (static/index.html): переключатели для
  bool (to_folder/to_dicom/use_network_share/web_trust_loopback), select
  для logs_level, datepicker (datetime-local) для start_date, number для
  портов/таймаутов, password для секретов; поля сгруппированы по секциям
  и блокируются при выключенном родительском стоке/шаре.

## 10. Продакшен-сборка (dist/rtlc.exe)

Один exe (`PyInstaller rtlc.spec`, onefile, ~18 МБ, без UPX) объединяет
все режимы (`rtlc_main.py`):

| Команда | Режим |
|---|---|
| `rtlc.exe` / `rtlc.exe gui` | Web UI на `http://127.0.0.1:8765/` |
| `rtlc.exe run` | консольный цикл копирования |

## 11. Доставка на DICOM-узел (C-STORE SCU)

Два независимых стока (`[Delivery] to_folder` / `to_dicom`, можно оба):
папка — как раньше (temp+rename), DICOM — C-STORE через pynetdicom
(`dicom_sender.py`, transfer syntax из мета-заголовка файла, пиксели не
декодируются). Обрабатываются только стабилизированные файлы.

- **Журнал по стокам**: запись файла — `{size, mtime, folder: {dest,
  done_at}, dicom: {sent, sent_at, attempts, last_error, permanent}}`.
  Файл завершён, когда приняли все включённые стоки; ретраится только
  упавший. Старые записи журнала мигрируются в новый формат при загрузке.
- **Классификация ошибок C-STORE**: транзиентные (нет ассоциации, сеть,
  0xA7xx) — ретрай каждый цикл; перманентные (не DICOM-файл, 0xCxxx) —
  файл завершается с пометкой, без бесконечного ретрая; warning
  (0xBxxx) считается доставкой.
- **Инвариант безопасности источника**: движок никогда не пишет и не
  удаляет в `remote` (покрыто тестом: байты и mtime источника неизменны).
- **`to_folder=false`**: папка `local` не требуется и не создаётся;
  в SMB-режиме файл для C-STORE материализуется во временный системный
  файл и удаляется сразу после отправки.
- **GUI**: галочки стоков и поля `[Dicom]` в настройках (валидация: оба
  стока выключены → 400; to_dicom без host/called_aet → 400), счётчики
  DICOM в статусе, колонка DICOM в журнале, кнопка C-ECHO
  (`POST /api/v1/dicom/echo`).
- **Тесты** (`tests/test_dicom_send.py`, 9 шт.): настоящий C-STORE SCP на
  pynetdicom — оба стока / только DICOM / узел лежит→поднялся (ретрай без
  дубля в папке) / не-DICOM → permanent / валидации / echo up/down /
  неизменность источника.
- Зависимости: + `pydicom`, `pynetdicom` (в requirements.txt и в exe).

## 13. Фильтр расширений: файлы без расширения ('.[empty]')

В `extension_file` можно перечислить маркер `.[empty]` — тогда копируются и
файлы без расширения: `.dcm,.bin,.[empty]` → dcm, bin и без расширения.
Парсинг — `parseExtensions()` (rtlc.py), сравнение имён — единый
`CopyUtility.matchName()` (локальный режим и SMB-режим службы). Пустой
фильтр по-прежнему принимает всё. В API статуса добавлено поле
`extensionNoExt`; GUI показывает маркер в строке фильтра.

## 12. Миграция SMB: pysmb (SMB1) → smbprotocol (SMB2/3) + прогон службы

**Почему.** pysmb говорит только SMB1 (NetBIOS, порт 139). На современной
Windows SMB1 отключён/отвергается: подключение рвалось с
`WinError 10054` ещё на этапе сессии — SMB-режим был фактически мёртв и
при этом нёс риск принудительного включения SMB1 на сервере (что
неприемлемо в медконтуре). Замена: `smbprotocol` (SMB2/3, подпись,
шифрование по умолчанию ОС).

**Что изменено:**
- `smbclient.py` (pysmb) удалён; новый `smb_client.py` — класс `SmbClient`
  (`register_session` / `delete_session` / `scandir` / `open_file`),
  поверх него без изменений логики работают стабилизация, ledger,
  temp+rename. Порт вынесен из хардкода 139 в `[NetShare] share_port`
  (default 445, валидация в webui.py, поле в GUI).
- **Квалификация имени пользователя**: NTLM из-под службы (LocalSystem)
  с незквалифицированным локальным именем (`user` без домена) получает
  `LOGON_DENIED` (WinError -2146893043) — из интерактивной сессии тот же
  логин работает. Воспроизведено изолированно через планировщик
  (задача от SYSTEM): `user` → FAIL, `.\user` → OK. В `SmbClient` к имени
  без квалификатора (`\` или `@`) автоматически добавляется `.\`;
  доменные учётки (`DOMAIN\user`, `user@domain`) не трогаются.
  Атрибутика `.\user` под NTLM корректна и для удалённого сервера
  (локальная учётка целевой машины).

**Проверено end-to-end (стенд, синтетика, без реальных данных):**
- Изолированный тест от SYSTEM (планировщик): connect + scandir +
  retrieve через `SmbClient`, байты копии совпали с источником.
- **Полный прогон службы под SCM**: созданы локальный пользователь и
  шара на loopback → `rtlc.exe install/start` (binpath `"...\rtlc.exe"
  service`, контекст LocalSystem) → в логе службы
  `Authenticated to //127.0.0.1/RTLC_SVC (SMB2/3)` → файл со шары
  скопирован после стабилизации (728 байт) → `cmp` подтвердил побайтовую
  идентичность → `stop`/`remove`, шара и пользователь удалены.
  Служба из одного exe: механика SCM и реальная доставка по SMB2/3
  работают вместе.
- Регрессия: 31/31 pytest. exe пересобран (`PyInstaller rtlc.spec`).
